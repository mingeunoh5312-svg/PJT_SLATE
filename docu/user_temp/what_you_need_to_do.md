# 수정 및 작업 사항 정리

작업 순위는 '사용자 직접 작성' 항목을 최우선으로 설정한다.
작업은 페이지 단위로 진행한다.

## 사용자 직접 작성

### 기능

#### 공통
1. (1차 필터 설정) 모든 페이지에 대한 1차 필터 설정
 - 서비스를 실제 배포하기 전 또는 서비스 점검 시 페이지에 접근하는 이용자들에게 안내 페이지를 제공해야 한다.
 - 서비스의 어떤 페이지 주소를 입력하더라도 해당 페이지로 이동되어야 한다.
2. (문구 출력) 이용자에게 제공되는 안내 문구는 가급적 호버링 방식으로 팝업한다.
 - 이용자에게 문구를 출력하는 모든 경우를 검토하고, 호버링 방식에서 제외할 케이스를 설정한다. 이 작업은 Codex 사용자에게 질문을 통해 판단을 요구해야 한다.
3. (이미지 클릭) 이용자가 서비스 이용 중 이미지(프로필 사진, 팀 대표 이미지, 공모전) 클릭 시 호버링으로 큰 이미지를 보여준다.
 - 작업물 게시판 썸네일 등 바로가기에 포함되는 이미지에는 해당 기능을 적용하지 않는다.

#### 메인 페이지

1. (비로그인) 'Slate에서 제작을 시작하는 방법' 블럭의 추가 기능
 - '조건에 맞는 매칭'은 '팀 생성하기'로 변경한다.
 - '제작팀과 모집 관리'는 '팀원 찾기'로 변경한다.
 - '공모전 탐색'은 '공모전 찾기'로 변경한다.
 - 각 영역을 클릭 시 해당 페이지(팀/매칭/공모전)로 이동한다.
2. (공통) '마감 임박 공모전' 항목
 - 해당 공모전에 업로드 된 이미지가 없는 경우 default 이미지를 출력한다.
 - 해당 공모전에 업로드 된 이미지가 있는 경우 해당 공모전 이미지를 출력한다.
3. (공통) '최근 등록된 작업물'
 - 해당 작업물에 업로드 된 이미지가 없는 경우 default 이미지를 출력한다.
    - Youtube 링크 등의 영상 썸네일이 있는 경우 썸네일을 출력한다.
 - 해당 작업물에 업로드 된 이미지가 있는 경우 해당 작업물 이미지를 출력한다.
4. (로그인) '지금 확인할 활동'에 표시될 항목 검증
 - 현재 일반/팀장 유저(김도윤) 로그인 시 '회사 승인 검토 요청'이 표시된다.
 - 유저의 구분에 따라 출력되는 내용을 제한할 수 있도록 검토한다.
 - 현재 팀원 유저(이지은) 로그인 시 '남산 새벽팀 추천 후보'가 출력되나, '확인' 버튼 클릭 시 해당 팀을 조회할 수 없다.
 - 팀 세부 정보는 아니더라도, '매칭 페이지 - 팀 찾기 - 저장한 팀'과 같이 해당 팀의 정보를 확인할 수 있어야 한다.
 - 페이지 우측 상단의 알림에도 동일한 문제가 발생하므로 함께 검증한다.

#### 매칭 페이지
1. (팀원 찾기) 팔로우 한 사용자 출력 추가
 - '팀 찾기' 탭의 '추천 팀', '저장한 팀'과 같이 하위 탭을 설정한다.
 - 하위 탭은 '전체', '팔로우'로 구분한다.
 - '전체' 탭은 현재 화면을 따른다.
 - '팔로우' 탭은 회원이 팔로우한 회원 목록에서 팀원을 찾을 수 있도록 구성한다.
2. (팀원 찾기 - 기준 정보) 기준 팀 출력 방식
 - 현재 이용자의 팀이 2개 이상인 경우 팀 목록을 지정할 수 있도록 지정되어 있다.
 - 이용자의 팀이 1개인 경우에도 2개 이상인 경우와 동일한 UI를 사용한다.
 - 기본값은 팀이 1개인 경우 해당 팀으로 지정하고, 2개 이상인 경우 '가장 최근 생성한 팀'으로 지정한다.
 - '모집 역할'은 복수 선택이 가능해야 한다. 복수 선택 방식은 3번 항목의 형식을 따른다.
 - 팀이 없는 팀원의 경우, 현재 출력 방식을 동일하게 적용한다.
3. (팀원 찾기 - 추가 필터) 필터 입력 방식
 - '지역' 필터는 현재 키워드 검색 후 하단 탭에서 클릭으로 지정하게 되어있다.
 - '지역' 필터의 두 탭을 하나로 합친다. 병합 방식은 DB에 입력된 정보를 바탕으로 이용자가 글자를 타이핑하는 경우 해당 글자를 포함하는 항목이 하단에 출력되도록 한다.
 - 한글 입력 시 한 글자의 입력을 다 마치지 않아도 해당 텍스트에 대한 지역 정보를 출력할 수 있어야 한다. 예를 들어, '고양'을 검색하는 경우 두 번째 글자에서 '고야'를 입력 중일 때 '고야'를 포함하는 텍스트를 즉각 하단에 출력하고, '고양'이 입력된 상태인 경우 '고양'을 포함하는 텍스트를 즉각 하단에 출력할 수 있어야 한다.
 - 위 수정 사항을 '장르'에 동일하게 적용한다. 미입력 상태에서는 전체 목록을 출력한다.
 - '장르', '합류 가능 시점'(작업 일정), '협업 조건'은 복수 선택이 가능해야 한다.
 - 복수 선택 시 '필터 적용/필터 초기화/AI로 팀원 추천받기'의 아래에 선택한 필터가 제시되어야 한다.
 - 복수 선택한 항목이 출력될 때 각 항목의 우측에 X 표시를 두어 설정을 취소할 수 있어야 한다.
 - 복수 선택한 항목은 각 필터별로 정렬되어 필터 순으로 표시되어야 하며, 각 필터에 따라 텍스트를 담는 배경의 색이 달라야 한다.
4. (팀원 찾기 - 필터) '필터 초기화' 버튼 클릭 시 '기준 팀'이 함께 초기화된다.
 - 기준 팀은 유지되도록 초기화 버튼과 연결을 분리한다.
5. (팀 찾기 - 필터) '추가 필터'에 '팀원 찾기'에서 '장르/지역/요구 경력/협업 조건'에 적용한 사항을 동일하게 적용한다.
6. (팀 찾기 - 필터) 검색 상태에서 필터 변경 시 기존 출력한 내용이 제거된다.
 - 필터 적용(팀 검색) 버튼을 누르기 전까지 기존 검색 내용은 유지하도록 수정한다.
 - 필터 초기화(초기화) 버튼을 누르는 경우에도 동일하게 기존 출력은 유지되도록 한다.

### 디자인

#### 공통
1. (prototype_2 참조) 데스크톱 브라우저 폭 변경 시 동적 웹페이지의 적용 범위 설정
 - 동적으로 늘어나거나 줄어드는 블럭의 크기에 제한이 설정되어야 한다.
 - 페이지의 최소 폭은 1920 화면의 절반인 960으로 가정한다.
 - 페이지 최소 폭 이하, 모바일 환경 전환 크기 이상인 경우 최소 폭인 960의 상태에서 요소(블럭, 버튼)들의 크기가 더 줄어서는 안된다.
2. (좌측 바 - 비로그인) 최하단 '관리자' 버튼을 '로그인'으로 변경
3. (버튼) 버튼 내 텍스트의 상하 정렬을 중앙으로 정렬
4. (반영 결과 출력) 버튼 클릭 시 결과 시각화 방식 수정
 - 현재 팀에 지원하는 경우 '이미 대기 중인 지원이 있습니다.'와 같은 문구를 최상단에 출력한다.
 - 기능 공통에 따라 호버링으로 출력하는 경우 호버링 방식을 우선으로 한다.
 - 이벤트가 발생하는 경우 출력되는 문구들은 각 버튼의 하단에 출력되어야 한다.
 - 버튼을 통해 활성화/비활성화가 이루어지는 요소들은 각 상태에 따른 시각화가 달라야 한다.
 - 비활성화 상태에서는 진하게, 활성화 상태에서는 연하게 표시한다.
5. (데스크톱) 화면이 최적으로 출력되는 최소 폭은 1310로 상정한다.

#### 메인 페이지

1. (메인 카드) 메인 카드 이미지 직접 지정
 - 현재 '모두가 영화인이 될 수 있다 | 함께 만들 다음 작품을 찾아보세요 ...'는 임시 이미지가 반영되어 있다.
 - 관리자가 이미지를 직접 지정하여 카드의 배경으로 사용할 수 있어야 한다.
 - 현재 방식은 좌측에 텍스트, 우측에 이미지로 지정되어있다. 이를 이미지가 배경으로 지정되도록 변경한다.
2. (비로그인) 메인 카드 텍스트
 - '무료로 시작하기', '작업물 둘러보기'는 유지한다.
 - '로그인'은 삭제한다.
3. (비로그인) '다음 작품을 함께 만들 사람을 만나보세요' 블럭 삭제
 - 메인 카드와 기능이 겹치므로 해당 블럭을 삭제한다.
4. (로그인, 공모전) '마감 임박 공모전'에서 '하트' 클릭 컨텐츠
 - 해당 컨텐츠를 별도로 확인할 수 있는 방법의 부재
 - 공모전 페이지의 '저장한 공모전'과 기능 중복
 - 두 기능을 병합하고 공모전 페이지의 상단 탭에서 '저장한 공모전'으로 별도 조회 기능을 구현한다.
 - 병합 시 디자인은 메인 페이지의 하트 아이콘을 채택한다.

#### 매칭 페이지
1. (팀원 찾기 - 추가 필터) 합류 가능 시점 항목 수정
 - '합류 가능 시점'을 '작업 일정'으로 수정한다.
 - '1개월 이후' 항목을 '6개월 이내'로 수정한다.
 - 데스트톱 웹을 기준으로 블럭이 최소 크기일 때 '장르', '지역', '경력', '작업 일정', '협업 조건'이 한 줄에 제시되어야 한다.
2. (팀/팀원 찾기) 필터 적용/필터 초기화/AI로 팀원 추천받기 항목 수정
 - 각 버튼을 팀(팀원) 검색/초기화/AI 추천 으로 변경한다.
 - '초기화' 버튼은 좌측 정렬로 가장 왼쪽에 배치한다.
 - '팀원 검색', 'AI 추천'은 'AI 추천'이 가장 오른쪽에 오도록 우측 정렬한다.

#### 팀 페이지
1. (내 팀 목록) 요소 제거
 - 내 팀 목록의 팀 우측에 별표로 표시되는 '관심 팀'은 본인 팀만 표시할 수 있으므로 모순된다.
 - '관심 팀' 기능과 별표 버튼은 삭제하고, 매칭 페이지 - 팀 찾기의 '저장' 버튼을 해당 기능의 메인으로 설정한다.
 - '팀 아카이브 안내'는 삭제한다.
2. (내 팀 목록/종료된 팀) 내 팀 목록에는 현재 진행 중인 팀(최대 3개)만 표시한다.
 - 종료 상태에 있는 팀은 '종료된 팀' 블럭에 별도로 출력되도록 한다.
 - '내 팀 목록'과 '종료된 팀' 항목은 각각 팀 생성일 최신순, 팀 종료일 최신순으로 출력한다.
 - '종료된 팀'은 같은 줄의 가장 오른쪽에 '최신순/오래된순'으로 정렬 방식을 설정할 수 있어야 한다.
3. (팀 목록) 디자인 요소 수정
 - 각 팀 정보에 표시되는 요소의 내용 및 디자인을 수정한다.
 - 가장 좌측에 팀 대표 이미지를 배치한다.
 - 이미지 우측에 팀 이름, 장르, 지역, 최신 일정, 모집 상황을 배치한다.
 - 가장 우측에 진행률 원그래프를 배치한다.
4. (팀 만들기) 디자인 요소 수정
 - 'Teams/팀 생성' 블럭은 삭제하고 하단의 '팀 정보' 블럭과 내용을 병합한다.
 - 현재 글자 크기로 'Teams/팀 생성'을 '팀 정보' 블럭의 최상단에 작성하고, 같은 줄에 우측 정렬로 '팀 목록', '팀 저장' 버튼을 제공한다.
 - '생성/팀 정보'는 삭제한다.
 - '상태' 영역의 폭을 글자수 크기 최대(모집 완료) 크기에 맞게 줄인다.
 - '상태'를 현재 줄의 가장 왼쪽에 배치한다.
 - '팀 이름'을 '상태'의 오른쪽에 배치한다.
 - '팀 대표 이미지/JPEG, PNG, WebP · 최대 5MB/이미지 선택'은 한 줄로 '상태'의 아래줄에 배치한다.
 - '지역 설정', '지역', '예상 기간', '최대 인원'은 '상태'와 같이 크기를 줄인다.
 - '지역 설정', '지역'과 '예상 기간', '최대 인원'을 각각 묶어 2개의 단으로 한 줄에 배치한다. 각각 왼쪽, 오른쪽으로 표시한다.
 - 각 '장르'의 버튼들에서 체크박스는 제거하고, 공통에 따라 활성화/비활성화로 체크 여부를 표시한다.
 - '이미지 미리보기'는 '상태', '팀 대표 이미지 텍스트' 두 줄과 동일한 줄의 가장 좌측에 배치한다.
 - '설명' 영역을 가장 아래쪽에 배치한다.
5. (팀 상세) 화면 구성
 - '모집 상태'(예:RECRUITING)는 팀 이미지 상단에 배치한다.
 - '정원'(예:2명/최대 6명)은 '팀 이름' 상단에 배치한다.
 - '설명'에 줄 띄기를 입력해도 하나의 줄로 작성되는 문제점을 수정한다.
 - '설명'을 길게 입력하는 경우 블럭이 과도하게 커지는 문제점이 발생한다.
 - '설명'이 500자가 넘어가는 경우 '더 보기'로 이후 내용을 생략하고, '더 보기' 클릭 시 전체 텍스트를 출력한다.
 - '설명'이 길어지는 경우 이미지가 블럭의 중앙으로 이동하므로, 팀 이미지는 위쪽 정렬로 고정한다.
 - '설명'에 숫자가 길게 입력되는 경우 줄 변경이 되지 않는 문제점을 수정한다.

## Codex 작성

작성 기준: `docu/plan`의 상위 명세와 `Slate/docu`의 MVP 범위, 구현 리뷰, 배포/검증 문서를 함께 반영했다.

현재 `Slate`는 프로토타입을 그대로 둔 상태가 아니라 최종 앱 후보로 이식된 상태다. 따라서 이미 반영된 항목과 아직 남은 항목을 구분해서 본다.

이미 반영된 주요 항목:

- JWT 인증/권한 구조
- 기능별 백엔드 패키지 분리
- 파일 스트리밍 접근 권한 검증
- 데모 접속 코드 gate 기본 구현
- OpenAI 호출 실패 시 점수 기반 추천 fallback
- MySQL 8 schema/seed 적용 검증
- 프론트엔드 production build 통과
