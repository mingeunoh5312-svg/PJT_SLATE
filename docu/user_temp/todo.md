# Slate 수정 작업 TODO

이 문서는 `what_you_need_to_do.md`의 `사용자 직접 작성` 내용을 기준으로 재정리한 작업 문서다.

작업 원칙:

- `사용자 직접 작성` 항목을 최우선 기준으로 삼는다.
- `Codex 작성` 항목은 사용자 작성 내용을 검증하거나 보조하는 범위에서만 반영한다.
- 코드 작업은 공통 작업과 페이지 단위 작업으로 나누어 진행한다.
- 원본에 작성된 세부 요소를 누락하지 않는다.
- 로그인/회원가입, 게시판, 공모전, 내 정보 페이지의 별도 수정 사항은 아직 사용자 작성 전이므로, 이 문서에는 현재 사용자 작성분과 직접 연결되는 항목만 포함한다.

## 1. 공통 작업

### 1.1 배포 전 또는 점검 중 안내 페이지

목표:

- 서비스를 실제 배포하기 전 또는 서비스 점검 시, 페이지에 접근하는 이용자에게 안내 페이지를 제공한다.
- 서비스의 어떤 페이지 주소를 직접 입력하더라도 안내 페이지를 거친 뒤 해당 페이지로 이동할 수 있어야 한다.

작업 내용:

- 전체 페이지에 적용되는 1차 접근 필터를 구현한다.
- 점검/배포 전 안내 페이지를 만든다.
- 사용자가 직접 입력한 원래 URL을 보존한다.
- 안내 페이지 통과 후 원래 URL로 이동시킨다.
- 프론트 라우터 접근뿐 아니라 API 직접 호출 차단이 필요한지 함께 검토한다.

확인 기준:

- `/`, `/matching/teams`, `/teams`, `/boards`, `/contests`, `/profile`, `/admin` 등 어떤 주소로 접근해도 안내 페이지가 먼저 표시된다.
- 안내 페이지 통과 후 원래 입력한 주소로 복귀한다.
- 새로고침 또는 직접 URL 접근 시에도 동일하게 동작한다.

보조 참고:

- 기존 `Codex 작성`의 demo gate, route 직접 접근/새로고침 검증은 이 작업의 보조 검증 기준으로만 사용한다.

### 1.2 안내 문구와 상태 메시지 출력 방식

목표:

- 이용자에게 제공되는 안내 문구는 가능한 한 데스크톱에서 hover 방식으로 보여준다.
- 모바일 환경에서는 hover를 사용할 수 없으므로 modal 또는 이에 준하는 터치 기반 UI로 대체한다.
- 모든 안내/오류/성공 문구를 검토하고, hover 또는 modal 방식에서 제외할 케이스를 정한다.

작업 내용:

- 서비스 전반의 안내 문구, 오류 문구, 성공 문구, 상태 문구 출력 위치를 조사한다.
- 데스크톱에서는 hover popover를 우선 적용한다.
- 모바일에서는 modal을 우선 적용한다.
- 버튼 클릭으로 발생하는 결과 문구는 각 버튼 하단에 출력한다.
- 현재처럼 `이미 대기 중인 지원이 있습니다.` 같은 문구를 화면 최상단에 출력하는 방식은 버튼 하단 출력으로 변경한다.
- hover/modal 방식이 적합하지 않은 문구는 별도 예외로 분류한다.

사용자 확인 필요:

- 어떤 문구를 hover/modal 대상에서 제외할지 구현 전에 사용자에게 질문한다.
- 예외 후보는 즉시 사라지면 안 되는 오류, 저장/삭제 성공 안내, 권한 없음, 로그인 필요, 폼 검증 오류, 서버 장애 안내다.

확인 기준:

- 데스크톱에서 hover 안내가 동작한다.
- 모바일에서 같은 안내가 modal로 표시된다.
- 버튼 결과 메시지는 버튼 하단에 표시된다.
- 화면 최상단에 임의로 떠 있는 결과 메시지가 남지 않는다.

### 1.3 이미지 확대 보기

목표:

- 이용자가 서비스 이용 중 이미지를 클릭하거나 hover할 때 큰 이미지를 확인할 수 있게 한다.

적용 대상:

- 프로필 사진
- 팀 대표 이미지
- 공모전 이미지

제외 대상:

- 작업물 게시판 썸네일
- 바로가기 기능을 포함하는 이미지
- 이미지를 클릭했을 때 상세 페이지 또는 다른 화면으로 이동해야 하는 이미지

작업 내용:

- 데스크톱에서는 이미지 hover 시 큰 이미지 preview를 제공한다.
- 모바일에서는 이미지 tap/click 시 modal로 큰 이미지를 보여준다.
- 이미지가 없는 경우 확대 기능을 노출하지 않는다.
- 확대 보기 UI는 닫기 동작을 명확히 제공한다.

확인 기준:

- 프로필 사진, 팀 대표 이미지, 공모전 이미지는 확대 확인이 가능하다.
- 작업물 게시판 썸네일 등 바로가기 이미지는 확대 기능이 적용되지 않는다.
- 모바일에서 hover에 의존하는 기능이 없다.

### 1.4 데스크톱 반응형 폭 기준

목표:

- 데스크톱 브라우저 폭 변경 시 동적으로 줄어드는 블럭과 버튼의 최소 크기를 제한한다.
- 모바일 전환 폭은 기존 설정을 유지한다.

작업 내용:

- 페이지 최소 폭 기준은 960px로 본다.
- 화면 폭이 960px 이하로 줄어도, 모바일 전환 폭 이전 구간에서는 페이지 요소가 960px 기준보다 더 작아지지 않도록 한다.
- 실제 브라우저나 페이지 전체를 960px 이하로 줄일 수 없게 만드는 것이 목표가 아니다.
- 동적으로 늘어나거나 줄어드는 블럭, 버튼, 필터 영역, 카드 영역에 최소 크기 제한을 둔다.
- 데스크톱에서 화면이 최적으로 출력되는 최소 폭은 1310px로 상정한다.

확인 기준:

- 1310px 이상에서는 데스크톱 최적 레이아웃이 유지된다.
- 960px 이상 1310px 미만에서는 요소가 과도하게 찌그러지지 않는다.
- 960px 이하부터 모바일 전환 폭 이전까지는 블럭과 버튼 크기가 더 줄어들지 않는다.
- 모바일 전환 폭 이하에서는 기존 모바일 레이아웃을 유지한다.

### 1.5 좌측 바, 버튼, 활성 상태 공통 디자인

작업 내용:

- 비로그인 상태 좌측 바 최하단의 `관리자` 버튼을 `로그인`으로 변경한다.
- 모든 버튼 내부 텍스트의 상하 정렬을 중앙으로 맞춘다.
- 버튼 또는 선택 요소의 활성/비활성 상태를 시각적으로 구분한다.
- 활성화 상태는 선택 또는 적용 상태임을 알 수 있도록 강조색, 선명한 배경, 높은 대비를 사용한다.
- 비활성화 상태는 선택되지 않았거나 적용되지 않은 상태임을 알 수 있도록 옅은 배경, 낮은 대비, 보조 텍스트 색을 사용한다.
- 장르 버튼처럼 체크박스를 제거하는 경우에도 활성/비활성 스타일로 선택 여부가 드러나야 한다.

확인 기준:

- 버튼 텍스트가 위아래로 치우치지 않는다.
- 로그인 전 좌측 바 최하단 버튼이 `로그인`으로 표시된다.
- 선택된 항목과 선택되지 않은 항목이 색상과 대비로 명확히 구분된다.

## 2. 메인 페이지

### 2.1 비로그인: `Slate에서 제작을 시작하는 방법` 블럭 수정

작업 내용:

- `조건에 맞는 매칭` 문구를 `팀 생성하기`로 변경한다.
- `제작팀과 모집 관리` 문구를 `팀원 찾기`로 변경한다.
- `공모전 탐색` 문구를 `공모전 찾기`로 변경한다.
- 각 영역을 클릭할 수 있게 만든다.
- `팀 생성하기` 클릭 시 팀 생성 또는 팀 페이지로 이동한다.
- `팀원 찾기` 클릭 시 매칭 페이지의 팀원 찾기 흐름으로 이동한다.
- `공모전 찾기` 클릭 시 공모전 페이지로 이동한다.

확인 기준:

- 비로그인 메인 페이지에서 세 문구가 변경되어 표시된다.
- 각 영역 클릭 시 지정된 페이지로 이동한다.

### 2.2 `마감 임박 공모전` 이미지 출력

작업 내용:

- 공모전에 업로드된 이미지가 없는 경우 default 이미지를 출력한다.
- 공모전에 업로드된 이미지가 있는 경우 해당 공모전 이미지를 출력한다.
- 공모전 이미지에는 공통 이미지 확대 보기 정책을 적용한다.

확인 기준:

- 이미지가 있는 공모전은 실제 공모전 이미지를 보여준다.
- 이미지가 없는 공모전은 default 이미지를 보여준다.
- 이미지 클릭 또는 hover/tap 시 큰 이미지 확인 방식이 적용된다.

### 2.3 `최근 등록된 작업물` 이미지 출력

작업 내용:

- 작업물에 업로드된 이미지가 있는 경우 해당 작업물 이미지를 출력한다.
- 작업물에 업로드된 이미지가 없는 경우 default 이미지를 출력한다.
- YouTube 링크 등 영상 썸네일이 있는 경우 default 이미지보다 영상 썸네일을 우선 출력한다.
- 작업물 게시판 썸네일은 바로가기 성격이 있으므로 공통 이미지 확대 보기 대상에서 제외한다.

확인 기준:

- 작업물 이미지가 있으면 작업물 이미지를 보여준다.
- 작업물 이미지가 없고 YouTube 썸네일이 있으면 YouTube 썸네일을 보여준다.
- 작업물 이미지와 YouTube 썸네일이 모두 없으면 default 이미지를 보여준다.
- 작업물 썸네일 클릭은 확대가 아니라 기존 이동 동작을 유지한다.

보조 참고:

- 기존 `Codex 작성`의 YouTube metadata/업로드 UI 검증은 이 작업의 보조 확인 기준으로만 사용한다.

### 2.4 로그인: `지금 확인할 활동` 항목 검증

확인된 문제:

- 일반/팀장 유저 `김도윤`으로 로그인 시 `회사 승인 검토 요청`이 표시된다.
- 팀원 유저 `이지은`으로 로그인 시 `남산 새벽팀 추천 후보`가 표시되지만, `확인` 버튼 클릭 시 해당 팀을 조회할 수 없다.
- 페이지 우측 상단 알림에도 같은 문제가 발생한다.

작업 내용:

- 유저 구분에 따라 `지금 확인할 활동`에 표시되는 내용을 제한한다.
- 일반 사용자, 팀장, 팀원, 회사, 관리자 등 계정/역할별로 노출 가능한 활동 항목을 검토한다.
- 일반/팀장 유저에게 회사 승인 검토 요청이 노출되지 않게 한다.
- 팀 추천 후보의 `확인` 버튼 클릭 시 팀 정보를 확인할 수 있게 한다.
- 팀 세부 정보로 바로 이동하기 어렵다면 `매칭 페이지 > 팀 찾기 > 저장한 팀`처럼 해당 팀 정보를 확인할 수 있는 경로로 연결한다.
- 우측 상단 알림의 같은 문제도 함께 검증하고 수정한다.

확인 기준:

- `김도윤` 로그인 시 회사 승인 검토 요청이 표시되지 않는다.
- `이지은` 로그인 시 `남산 새벽팀 추천 후보`의 확인 버튼으로 관련 팀 정보를 확인할 수 있다.
- 우측 상단 알림에서도 같은 유형의 잘못된 노출 또는 잘못된 이동이 없다.

### 2.5 메인 카드 이미지와 텍스트

작업 내용:

- 현재 `모두가 영화인이 될 수 있다 | 함께 만들 다음 작품을 찾아보세요 ...` 메인 카드에 임시 이미지가 반영되어 있으므로, 관리자가 이미지를 직접 지정할 수 있게 한다.
- 관리자가 지정한 이미지를 메인 카드 배경으로 사용한다.
- 현재 좌측 텍스트, 우측 이미지 구조를 이미지 배경 구조로 변경한다.
- 비로그인 메인 카드의 `무료로 시작하기`, `작업물 둘러보기`는 유지한다.
- 비로그인 메인 카드의 `로그인`은 삭제한다.

확인 기준:

- 메인 카드 이미지가 우측 분할 이미지가 아니라 배경 이미지로 표시된다.
- 관리자 지정 이미지가 메인 카드 배경으로 반영된다.
- 비로그인 상태에서 `무료로 시작하기`, `작업물 둘러보기`만 남고 `로그인` 버튼은 보이지 않는다.

### 2.6 비로그인 중복 블럭 삭제

작업 내용:

- 비로그인 메인 페이지의 `다음 작품을 함께 만들 사람을 만나보세요` 블럭을 삭제한다.
- 삭제 이유는 메인 카드와 기능이 겹치기 때문이다.

확인 기준:

- 비로그인 메인 페이지에서 해당 블럭이 더 이상 표시되지 않는다.
- 삭제 후 페이지 흐름에 빈 공간이나 어색한 간격이 남지 않는다.

### 2.7 메인 공모전 하트와 저장한 공모전 통합

문제:

- 메인 페이지 `마감 임박 공모전`의 하트 클릭 컨텐츠를 별도로 확인할 방법이 없다.
- 공모전 페이지의 `저장한 공모전` 기능과 중복된다.

작업 내용:

- 메인 페이지의 공모전 하트 기능과 공모전 페이지의 `저장한 공모전` 기능을 병합한다.
- 공모전 페이지 상단 탭에 `저장한 공모전`을 별도 조회 기능으로 구현한다.
- 병합 시 디자인은 메인 페이지의 하트 아이콘을 채택한다.

확인 기준:

- 메인 페이지에서 하트를 누른 공모전을 공모전 페이지의 `저장한 공모전` 탭에서 확인할 수 있다.
- 공모전 페이지의 저장 기능도 동일한 저장 상태를 사용한다.
- 하트 아이콘 디자인은 메인 페이지 디자인을 기준으로 통일된다.

## 3. 매칭 페이지

### 3.1 팀원 찾기: 팔로우한 사용자 출력 추가

작업 내용:

- 팀원 찾기 화면에 하위 탭을 추가한다.
- 하위 탭 구조는 팀 찾기 탭의 `추천 팀`, `저장한 팀`처럼 구성한다.
- 팀원 찾기 하위 탭은 `전체`, `팔로우`로 구분한다.
- `전체` 탭은 현재 팀원 찾기 화면을 따른다.
- `팔로우` 탭은 회원이 팔로우한 회원 목록에서 팀원을 찾을 수 있도록 구성한다.

확인 기준:

- 팀원 찾기 화면에 `전체`, `팔로우` 탭이 표시된다.
- `전체` 탭은 기존 팀원 찾기 결과를 보여준다.
- `팔로우` 탭은 로그인 사용자가 팔로우한 회원을 기준으로 팀원 후보를 보여준다.

### 3.2 팀원 찾기: 기준 팀 출력 방식

작업 내용:

- 현재 이용자의 팀이 2개 이상인 경우 팀 목록을 지정할 수 있는 기존 UI를 유지한다.
- 이용자의 팀이 1개인 경우에도 2개 이상인 경우와 동일한 UI를 사용한다.
- 팀이 1개인 경우 기본값은 해당 팀으로 지정한다.
- 팀이 2개 이상인 경우 기본값은 `가장 최근 생성한 팀`으로 지정한다.
- 팀이 없는 팀원의 경우 현재 출력 방식을 동일하게 적용한다.
- `모집 역할`은 복수 선택이 가능해야 한다.
- `모집 역할` 복수 선택 방식은 추가 필터 복수 선택 방식과 동일하게 적용한다.

확인 기준:

- 팀 1개 보유 사용자는 팀 선택 UI가 표시되고 해당 팀이 기본 선택된다.
- 팀 2개 이상 보유 사용자는 가장 최근 생성한 팀이 기본 선택된다.
- 팀이 없는 사용자는 기존 안내/빈 상태가 유지된다.
- 모집 역할을 복수 선택할 수 있다.

### 3.3 팀원 찾기: 지역 필터 입력 방식

현재 상태:

- 지역 필터는 키워드 검색 후 하단 탭에서 클릭으로 지정하는 방식이다.

작업 내용:

- 지역 필터의 두 탭을 하나로 합친다.
- DB에 입력된 지역 정보를 기준으로 자동완성 목록을 제공한다.
- 이용자가 글자를 타이핑하면 해당 글자를 포함하는 지역 항목을 하단에 즉시 출력한다.
- 한글 입력 중 조합이 완료되지 않아도 현재 입력 중인 텍스트를 기준으로 지역 정보를 출력한다.
- 예를 들어 `고양`을 검색할 때 두 번째 글자 입력 중 `고야` 상태이면 `고야`를 포함하는 텍스트를 즉시 출력한다.
- `고양` 입력이 완료된 상태이면 `고양`을 포함하는 텍스트를 즉시 출력한다.

확인 기준:

- 지역 필터가 하나의 검색/선택 UI로 통합된다.
- 한글 조합 중에도 즉시 검색 결과가 갱신된다.
- 검색 결과는 DB에 입력된 지역 정보만 사용한다.

### 3.4 팀원 찾기: 장르 필터 입력 방식

작업 내용:

- 지역 필터의 수정 방식을 장르 필터에도 동일하게 적용한다.
- DB에 입력된 장르 정보를 기준으로 자동완성 목록을 제공한다.
- 미입력 상태에서는 전체 장르 목록을 출력한다.
- 글자를 입력하면 해당 글자를 포함하는 장르 항목을 즉시 출력한다.
- 한글 입력 중 조합이 완료되지 않아도 현재 입력 중인 텍스트를 기준으로 장르 정보를 출력한다.

확인 기준:

- 미입력 상태에서 전체 장르가 보인다.
- 입력 중인 텍스트에 맞춰 장르 목록이 즉시 필터링된다.
- 장르 목록은 DB 기준 데이터와 일치한다.

### 3.5 팀원 찾기: 복수 선택 필터와 선택 칩

적용 대상:

- 장르
- 합류 가능 시점, 단 화면 표시명은 `작업 일정`
- 협업 조건
- 모집 역할

작업 내용:

- 위 항목들은 복수 선택이 가능해야 한다.
- 복수 선택 시 `필터 적용/필터 초기화/AI로 팀원 추천받기` 버튼 아래에 선택한 필터가 표시되어야 한다.
- 표시되는 각 선택 항목의 우측에는 X 표시를 두어 해당 설정을 취소할 수 있게 한다.
- 선택 항목은 필터별로 정렬한다.
- 선택 항목 표시 순서는 필터 순서를 따른다.
- 각 필터에 따라 텍스트를 담는 배경색을 다르게 한다.

확인 기준:

- 복수 선택한 항목이 버튼 아래에 칩 형태로 표시된다.
- 각 칩의 X를 누르면 해당 선택만 제거된다.
- 칩은 필터별로 묶이고 필터 순서대로 표시된다.
- 필터 종류별 배경색이 다르다.

### 3.6 팀원 찾기: 필터 초기화와 기준 팀 분리

문제:

- 현재 `필터 초기화` 버튼 클릭 시 `기준 팀`이 함께 초기화된다.

작업 내용:

- `필터 초기화` 버튼은 추가 필터 영역만 초기화해야 한다.
- 기준 팀은 초기화 버튼과 연결을 분리한다.
- 기준 팀, 모집 역할의 유지/초기화 범위를 명확히 분리한다.

확인 기준:

- 필터 초기화 클릭 후에도 기준 팀은 유지된다.
- 추가 필터만 초기화된다.
- 모집 역할이 기준 정보에 속하는 경우, 사용자 작성 기준에 따라 기준 정보로 유지되도록 처리한다.

### 3.7 팀 찾기: 추가 필터 개선

작업 내용:

- 팀 찾기 `추가 필터`에도 팀원 찾기에서 개선한 필터 방식을 동일하게 적용한다.
- 적용 대상은 `장르`, `지역`, `요구 경력`, `협업 조건`이다.
- 지역과 장르는 검색/자동완성/한글 조합 중 즉시 검색 방식을 따른다.
- 복수 선택 가능한 항목은 선택 칩과 X 제거 방식을 따른다.

확인 기준:

- 팀 찾기에서도 장르/지역/요구 경력/협업 조건 필터가 개선된 방식으로 동작한다.
- 팀원 찾기와 팀 찾기의 필터 UX가 일관된다.

보조 참고:

- 기존 `Codex 작성`의 `팀 찾기 장르 필터 백엔드 수정`은 이 작업의 보조 항목으로 반영한다.
- 프론트 필터 UI가 정상이어도 백엔드에서 장르 필터 결과가 0건으로 고정되면 함께 수정한다.

### 3.8 팀 찾기: 필터 변경과 초기화 시 기존 검색 내용 유지

작업 내용:

- 검색 상태에서 필터를 변경해도 기존 출력 내용은 제거하지 않는다.
- `팀 검색` 버튼을 누르기 전까지 기존 검색 결과를 유지한다.
- `초기화` 버튼을 누르는 경우에도 기존 검색 결과는 유지한다.
- 초기화 버튼은 필터 영역만 초기화한다.
- 필터 값이 변경되었지만 아직 검색 결과에 반영되지 않은 상태임을 사용자가 알 수 있게 표시한다.

확인 기준:

- 팀 찾기 결과가 표시된 상태에서 필터를 바꿔도 결과 목록은 사라지지 않는다.
- 초기화 버튼을 눌러도 결과 목록은 사라지지 않고 필터 영역만 초기화된다.
- 변경한 필터는 `팀 검색` 버튼을 눌렀을 때 결과에 반영된다.

### 3.9 매칭 페이지 필터 문구와 버튼 배치

작업 내용:

- 팀원 찾기 추가 필터의 `합류 가능 시점`을 `작업 일정`으로 변경한다.
- `1개월 이후` 항목을 `6개월 이내`로 변경한다.
- 데스크톱 웹 기준 블럭이 최소 크기일 때 `장르`, `지역`, `경력`, `작업 일정`, `협업 조건`이 한 줄에 제시되어야 한다.
- `필터 적용` 버튼 문구는 대상에 따라 `팀원 검색` 또는 `팀 검색`으로 변경한다.
- `필터 초기화` 버튼 문구는 `초기화`로 변경한다.
- `AI로 팀원 추천받기` 등 AI 버튼 문구는 `AI 추천`으로 변경한다.
- `초기화` 버튼은 좌측 정렬로 가장 왼쪽에 배치한다.
- `팀원 검색` 또는 `팀 검색` 버튼과 `AI 추천` 버튼은 우측 정렬한다.
- 우측 정렬 버튼 중 `AI 추천`이 가장 오른쪽에 오도록 배치한다.

확인 기준:

- 문구가 지정된 이름으로 변경된다.
- 최소 데스크톱 폭에서도 다섯 필터가 한 줄에 배치된다.
- 버튼 정렬이 좌측 `초기화`, 우측 `검색`, 최우측 `AI 추천` 순서로 보인다.

### 3.10 매칭 페이지 상태 UX 보조 검증

작업 내용:

- 사용자 작성 작업과 연결되는 범위에서 매칭 화면 상태를 검증한다.
- 필터 미적용, 필터 변경 후 검색 전, 결과 0건, API 오류, AI 실패 fallback, 저장/지원 상태를 구분한다.

확인 기준:

- 각 상태가 서로 다른 메시지와 버튼 상태로 표시된다.
- 필터 변경 또는 초기화 시 기존 검색 결과 유지 정책과 충돌하지 않는다.

## 4. 팀 페이지

### 4.1 내 팀 목록: 관심 팀 요소 제거

문제:

- 내 팀 목록의 팀 우측에 별표로 표시되는 `관심 팀`은 본인 팀만 표시할 수 있으므로 모순된다.

작업 내용:

- 내 팀 목록에서 `관심 팀` 기능을 삭제한다.
- 내 팀 목록에서 별표 버튼을 삭제한다.
- `팀 아카이브 안내`를 삭제한다.
- 팀 저장 또는 관심 기능의 메인은 `매칭 페이지 > 팀 찾기`의 `저장` 버튼으로 둔다.

확인 기준:

- 내 팀 목록에서 별표와 관심 팀 기능이 보이지 않는다.
- 팀 저장 기능은 매칭 페이지 팀 찾기 흐름에서만 주 기능으로 제공된다.
- 팀 아카이브 안내가 보이지 않는다.

### 4.2 내 팀 목록과 종료된 팀 분리

작업 내용:

- 내 팀 목록에는 현재 진행 중인 팀만 표시한다.
- 현재 진행 중인 팀은 최대 3개까지 표시한다.
- 종료 상태의 팀은 `종료된 팀` 블럭에 별도로 출력한다.
- `내 팀 목록`은 팀 생성일 최신순으로 출력한다.
- `종료된 팀`은 팀 종료일 최신순으로 출력한다.
- `종료된 팀` 블럭 같은 줄의 가장 오른쪽에 `최신순/오래된순` 정렬 방식을 설정할 수 있어야 한다.

확인 기준:

- 진행 중 팀과 종료된 팀이 섞이지 않는다.
- 내 팀 목록에는 최대 3개의 진행 중 팀만 표시된다.
- 종료된 팀은 별도 블럭에서 확인할 수 있다.
- 종료된 팀 정렬을 최신순/오래된순으로 바꿀 수 있다.

### 4.3 팀 목록 카드 디자인

작업 내용:

- 각 팀 정보에 표시되는 요소의 내용과 디자인을 수정한다.
- 가장 좌측에 팀 대표 이미지를 배치한다.
- 이미지 우측에 팀 이름, 장르, 지역, 최신 일정, 모집 상황을 배치한다.
- 가장 우측에 진행률 원그래프를 배치한다.
- 팀 대표 이미지에는 공통 이미지 확대 보기 정책을 적용한다.

확인 기준:

- 팀 목록 카드가 좌측 이미지, 중앙 정보, 우측 진행률 원그래프 구조로 표시된다.
- 팀 이름, 장르, 지역, 최신 일정, 모집 상황이 모두 표시된다.

### 4.4 팀 만들기: 상단 구조와 버튼

작업 내용:

- `Teams/팀 생성` 블럭을 삭제한다.
- 하단의 `팀 정보` 블럭과 내용을 병합한다.
- 현재 글자 크기로 `Teams/팀 생성`을 `팀 정보` 블럭 최상단에 작성한다.
- 같은 줄 우측 정렬로 `팀 목록`, `팀 저장` 버튼을 제공한다.
- `생성/팀 정보` 문구는 삭제한다.
- `팀 수정` 블럭의 `매칭` 버튼은 삭제한다.

확인 기준:

- 팀 만들기 화면에 별도의 `Teams/팀 생성` 블럭이 없다.
- `팀 정보` 블럭 최상단에 `Teams/팀 생성`이 표시된다.
- 우측에 `팀 목록`, `팀 저장` 버튼이 보인다.
- `생성/팀 정보` 문구와 `매칭` 버튼이 보이지 않는다.

### 4.5 팀 만들기: 입력 필드 배치

작업 내용:

- `상태` 영역의 폭을 글자 수가 가장 긴 상태값인 `모집 완료` 크기에 맞게 줄인다.
- `상태`를 현재 줄의 가장 왼쪽에 배치한다.
- `팀 이름`을 `상태` 오른쪽에 배치한다.
- `팀 대표 이미지/JPEG, PNG, WebP · 최대 5MB/이미지 선택`은 한 줄로 `상태` 아래줄에 배치한다.
- `지역 설정`, `지역`, `예상 기간`, `최대 인원`은 `상태`와 같이 크기를 줄인다.
- `지역 설정`, `지역`을 하나의 묶음으로 둔다.
- `예상 기간`, `최대 인원`을 하나의 묶음으로 둔다.
- 위 두 묶음을 2개의 단으로 한 줄에 배치한다.
- 두 묶음은 각각 왼쪽, 오른쪽에 표시한다.
- 각 `장르` 버튼에서 체크박스를 제거한다.
- 장르 선택 여부는 공통 활성/비활성 스타일로 표시한다.
- `이미지 미리보기`는 `상태`, `팀 대표 이미지 텍스트` 두 줄과 동일한 줄의 가장 좌측에 배치한다.
- `설명` 영역을 가장 아래쪽에 배치한다.

확인 기준:

- 상태와 주요 입력 필드가 지정된 줄과 단 구조로 배치된다.
- 장르 버튼에는 체크박스가 없고 선택 상태는 스타일로 구분된다.
- 이미지 미리보기와 설명 영역 위치가 지정대로 정리된다.

### 4.6 팀 상세: 상단 정보 배치

작업 내용:

- `모집 상태` 예: `RECRUITING`은 팀 이미지 상단에 배치한다.
- `정원` 예: `2명/최대 6명`은 팀 이름 상단에 배치한다.
- `목록`, `팀 수정` 버튼은 팀 이름 줄의 가장 오른쪽에 배치한다.
- 순서는 `팀 수정` 버튼이 가장 오른쪽에 위치하도록 한다.
- `목록` 문구는 `팀 목록`으로 변경한다.
- `팀 수정` 문구는 `팀 정보 수정`으로 변경한다.
- `리더`는 `장르`, `지역` 표기의 왼쪽에 배치한다.

확인 기준:

- 모집 상태, 정원, 팀 이름, 버튼, 리더/장르/지역 정보가 지정된 위치에 표시된다.

### 4.7 팀 상세: 설명 영역

문제:

- 설명에 줄 띄기를 입력해도 하나의 줄로 작성된다.
- 설명을 길게 입력하면 블럭이 과도하게 커진다.
- 설명이 길어질 때 이미지가 블럭 중앙으로 이동한다.
- 설명에 긴 숫자를 입력하면 줄 변경이 되지 않는다.

작업 내용:

- 설명의 줄바꿈을 보존한다.
- 설명이 500자를 넘어가면 `더 보기`로 이후 내용을 생략한다.
- `더 보기` 클릭 시 전체 텍스트를 출력한다.
- 설명이 길어져도 팀 이미지는 위쪽 정렬로 고정한다.
- 긴 숫자나 긴 단어도 영역 안에서 줄바꿈되도록 처리한다.

확인 기준:

- 줄바꿈 입력이 화면에 반영된다.
- 500자 초과 설명은 접힌 상태로 표시된다.
- 더 보기 클릭 시 전체 설명이 표시된다.
- 긴 텍스트가 레이아웃을 깨지 않는다.
- 팀 이미지는 위쪽 정렬을 유지한다.

### 4.8 팀 상세: 대기/모집/멤버 블럭 재배치

작업 내용:

- 설명 우측의 `지원/초대 대기`, `모집 슬롯 요약`, `멤버 현황`을 현재 위치한 블럭 아래에 별도 블럭으로 배치한다.
- `지원/초대 대기` 문구를 `모집 대기`로 변경한다.
- `모집 슬롯 요약` 문구를 `모집 현황`으로 변경한다.
- `멤버 현황` 문구를 `멤버 보기`로 변경한다.
- `모집 관리`, `멤버 관리`, `계획 보기` 버튼은 삭제한다.
- 버튼 3개의 기능 진입점은 이미 `모집 대기`, `모집 현황`, `멤버 보기` 블럭으로 제공되므로 별도 버튼은 유지하지 않는다.

확인 기준:

- 세 정보 영역이 설명 아래 별도 블럭으로 보인다.
- 명칭이 `모집 대기`, `모집 현황`, `멤버 보기`로 변경된다.
- `모집 관리`, `멤버 관리`, `계획 보기` 버튼이 보이지 않는다.
- 각 기능은 새 블럭을 통해 접근 가능하다.

### 4.9 팀 상세: 계획 진행률과 일정 안내

작업 내용:

- `계획 진행률`의 `전체 진행률` 그래프는 한 줄로 할당한다.
- 전체 진행률 그래프는 좌우 기준 중앙 정렬한다.
- `다음 마일스톤` 텍스트는 제거한다.
- D-Day 표시는 계획 진행률 바로 오른쪽에 배치한다.
- 기존 원 그래프 우측의 `최신 일정 제목`, `일자`는 그래프 아래 줄로 위치시킨다.
- `일정 안내`의 선 이미지 표시에서 일정이 조밀할 때 하단 텍스트가 겹치는 문제를 해결한다.
- `일정 안내`의 점들은 상대적인 위치를 반영하되 텍스트가 겹치지 않게 표시한다.
- 모바일 화면에서는 손으로, 데스크톱 화면에서는 마우스로 우측 일정들을 확인할 수 있도록 스위핑 기능을 적용한다.
- `일정 안내`의 각 일정에 표시되는 일정 상태 예: `진행 중`, `대기`는 텍스트 블럭의 일자 예: `2026년 6월 30일` 줄 가장 오른쪽에 배치한다.

확인 기준:

- 진행률 그래프와 D-Day가 지정된 위치에 표시된다.
- 최신 일정 제목과 일자는 그래프 아래 줄에 표시된다.
- 일정 텍스트가 서로 겹치지 않는다.
- 모바일 터치와 데스크톱 마우스 조작으로 우측 일정을 확인할 수 있다.

### 4.10 팀 상세: 종료/재개 관리와 팀 종료 페이지 분리

작업 내용:

- `계획 조작`을 삭제한다.
- `일정 안내` 블럭 아래 줄 가장 오른쪽에 `종료/재개 관리` 버튼을 배치한다.
- `종료/재개 관리` 문구를 `팀 작업 종료하기`로 변경한다.
- 현재 `팀 작업 종료하기` 클릭 시 `팀 수정` 페이지가 출력되는 문제를 수정한다.
- `팀 종료` 페이지를 별도로 생성한다.
- `팀 종료` 페이지에는 `팀 정보` 블럭을 제외하고 `팀 종료` 블럭만 출력한다.
- 기존 `팀 수정` 페이지에서는 `팀 종료` 블럭을 제거한다.

확인 기준:

- 팀 상세에서 `팀 작업 종료하기` 버튼을 클릭하면 별도 팀 종료 페이지로 이동한다.
- 팀 종료 페이지에는 팀 종료 블럭만 표시된다.
- 팀 수정 페이지에는 팀 종료 블럭이 남아 있지 않다.

### 4.11 팀 종료와 팀 복구 UI

작업 내용:

- `팀 종료` 블럭에서 `정상 종료` 버튼 클릭 시 데스크톱에서는 hover/popover 방식으로 확인 UI를 표시한다.
- 모바일에서는 같은 확인 UI를 modal로 표시한다.
- 확인 UI에는 `팀 작업을 종료하시겠습니까?` 텍스트와 `취소`, `작업 종료` 버튼을 표시한다.
- 종료 상태 팀의 `팀 종료` 블럭에 표시되는 `복구 스냅샷`, `복구 방식`은 제거한다.
- UI에서는 최신 팀 상태로 복구하는 단일 방식만 제공한다.
- 서비스 이용자에게 감사 로그와 종료 스냅샷 보관 정보는 제공하지 않는다.
- 단, 내부 시스템의 감사 로그와 종료 스냅샷 보관 자체는 UI 단순화와 별개로 유지한다.
- 종료 유형에 따라 안내 텍스트를 다르게 표시한다.
- 정상 종료 유형은 `팀 작업이 종료된 팀입니다.`로 표시한다.
- 해체 유형은 `해체된 팀입니다.`로 표시한다.
- 안내 텍스트는 블럭 안의 텍스트 블럭으로 표시한다.
- 정상 종료 안내는 초록 계열로 표시한다.
- 해체 안내는 빨간 계열로 표시한다.
- `팀 재개` 문구는 `팀 복구`로 변경한다.

확인 기준:

- 데스크톱에서 정상 종료 클릭 시 확인 UI가 hover/popover로 표시된다.
- 모바일에서 정상 종료 클릭 시 확인 UI가 modal로 표시된다.
- `복구 스냅샷`, `복구 방식` 문구가 사용자 UI에 표시되지 않는다.
- `팀 복구`는 단일 복구 방식으로 보인다.
- 종료 유형별 안내 문구와 색상이 다르게 표시된다.

## 5. 아직 사용자 작성 전인 페이지

아래 페이지는 사용자가 아직 수정 사항을 작성하지 않은 영역이다. 이 문서에서는 별도 작업 항목을 만들지 않는다.

- 로그인/회원가입
- 게시판
- 공모전
- 내 정보

단, 메인 페이지의 공모전 저장, 최근 작업물 썸네일, 공통 이미지 정책처럼 사용자 작성 항목과 직접 연결되는 범위는 포함한다.

## 6. 사용자 확인이 필요한 항목

코드 작업자가 구현 전에 반드시 사용자에게 확인해야 하는 항목:

1. 안내/오류/성공/상태 문구 중 hover/modal 방식에서 제외할 케이스
2. 점검/배포 전 안내 페이지의 실제 문구
3. 1차 접근 필터를 항상 켤지, 환경변수 또는 관리자 설정으로 켤지
4. 메인 카드 배경 이미지를 관리자가 어디에서 등록/수정할지
5. 팀 종료 페이지의 URL과 메뉴 노출 방식

현재 문서 작성 단계에서는 위 항목을 질문으로 남기고, 세부 구현 직전 사용자 확인을 받는다.

## 7. 권장 작업 순서

1. 공통 접근 필터, 안내 문구, 이미지 확대 정책을 먼저 정리한다.
2. 메인 페이지의 비로그인/로그인 활동 카드와 이미지 정책을 수정한다.
3. 매칭 페이지의 팀원 찾기 필터 구조와 팀 찾기 필터 유지 정책을 수정한다.
4. 팀 페이지 목록, 팀 만들기, 팀 상세, 팀 종료 페이지를 순서대로 수정한다.
5. 각 페이지 수정 후 데스크톱 1310px, 960px 경계, 모바일 기존 전환 폭 이하에서 확인한다.
6. 사용자 작성 전인 로그인/회원가입, 게시판, 공모전, 내 정보 페이지는 별도 사용자 작성 후 후속 문서로 반영한다.
