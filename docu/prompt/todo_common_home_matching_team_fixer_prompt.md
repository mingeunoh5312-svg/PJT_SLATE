## 공통 구현 상세

### 1. 접근 필터와 안내 페이지

요구사항:

- 서비스를 실제 배포하기 전 또는 점검 시 페이지 접근자에게 안내 페이지를 제공합니다.
- 어떤 페이지 주소를 입력해도 안내 페이지를 거친 뒤 해당 페이지로 이동할 수 있어야 합니다.
- 사용자가 입력한 원래 URL을 보존하고, 안내 페이지 통과 후 복귀시킵니다.
- 프론트 route gate와 백엔드 API 직접 호출 차단 필요성을 함께 검토합니다.

기준:

- 기존 `DemoAccessView`, `DemoAccessFilter`, `DemoAccessProperties`, `VITE_DEMO_ACCESS_GATE`, `SLATE_DEMO_ACCESS_ENABLED` 구조를 우선 확인합니다.
- 기존 demo gate와 목적이 겹치면 새 구조를 만들기보다 확장 또는 설정 분리 방식으로 구현합니다.
- 실제 접속 코드나 secret은 코드, 문서, 로그에 기록하지 않습니다.

완료 기준:

- `/`, `/matching/teams`, `/teams`, `/boards`, `/contests`, `/profile`, `/admin` 등 직접 접근이 안내 페이지를 거칩니다.
- 안내 페이지 통과 후 원래 URL로 복귀합니다.
- 새로고침과 직접 URL 접근에서도 동일하게 동작합니다.

### 2. 안내 문구와 상태 메시지

요구사항:

- 데스크톱에서는 hover popover를 우선 사용합니다.
- 모바일에서는 hover가 없으므로 modal 또는 터치 기반 UI로 대체합니다.
- 버튼 클릭 결과 메시지는 화면 최상단이 아니라 각 버튼 하단에 출력합니다.
- `이미 대기 중인 지원이 있습니다.` 같은 메시지는 해당 버튼 또는 action 영역 아래에 표시합니다.
- hover/modal 제외 케이스는 사용자 답변에 따릅니다.

완료 기준:

- 데스크톱과 모바일 모두 안내를 확인할 수 있습니다.
- 모바일에서 hover에만 의존하는 안내가 없습니다.
- 버튼 결과 메시지가 action 주변에 표시됩니다.

### 3. 이미지 확대 보기

적용:

- 프로필 사진
- 팀 대표 이미지
- 공모전 이미지

제외:

- 작업물 게시판 썸네일
- 바로가기 기능을 포함하는 이미지
- 클릭 시 상세 페이지나 다른 화면으로 이동해야 하는 이미지

구현 기준:

- 데스크톱: hover preview 또는 명확한 click preview
- 모바일: tap/click modal
- 이미지가 없는 경우 확대 기능을 노출하지 않음
- 닫기 동작과 접근성 속성을 제공

### 4. 반응형 폭 기준

요구사항:

- 모바일 전환 폭은 기존 설정을 유지합니다.
- 데스크톱 최적 최소 폭은 1310px로 봅니다.
- 페이지 최소 폭 기준은 960px입니다.
- 화면 폭이 960px 이하로 줄어도, 모바일 전환 폭 이전 구간에서는 블럭과 버튼이 960px 기준보다 더 줄어들지 않게 합니다.
- 실제 페이지 전체를 960px 이하로 줄일 수 없게 만드는 것이 목표가 아닙니다.

확인:

- 1310px
- 960px 경계
- 기존 모바일 전환 폭 이하
- 390x844 모바일

### 5. 좌측 바와 버튼 공통 스타일

요구사항:

- 비로그인 좌측 바 최하단 `관리자` 버튼을 `로그인`으로 변경합니다.
- 버튼 텍스트 상하 정렬을 중앙으로 맞춥니다.
- 활성 상태는 강조색, 선명한 배경, 높은 대비를 사용합니다.
- 비활성 상태는 옅은 배경, 낮은 대비, 보조 텍스트 색을 사용합니다.
- 체크박스를 제거한 선택 버튼도 활성/비활성 스타일로 선택 여부가 보여야 합니다.

## 메인 페이지 구현 상세

대상 우선 파일:

- `frontend/src/views/HomeView.vue`
- `frontend/src/styles/slate.css`
- `frontend/src/services/api.js`
- 필요 시 `backend/src/main/java/com/slate/contests`, `backend/src/main/java/com/slate/boards`, `backend/src/main/java/com/slate/notifications`

### 1. 비로그인 `Slate에서 제작을 시작하는 방법`

- `조건에 맞는 매칭` → `팀 생성하기`
- `제작팀과 모집 관리` → `팀원 찾기`
- `공모전 탐색` → `공모전 찾기`
- 각 영역을 클릭 가능하게 만들고, 팀/매칭/공모전 페이지로 이동시킵니다.

### 2. 마감 임박 공모전 이미지

- 업로드 이미지가 있으면 공모전 이미지를 출력합니다.
- 없으면 default 이미지를 출력합니다.
- 공통 이미지 확대 보기 정책을 적용합니다.
- 최근 공모전 구조화 작업과 `urgent` API 동작을 확인하세요.

### 3. 최근 등록된 작업물 이미지

- 업로드 이미지가 있으면 작업물 이미지를 출력합니다.
- 업로드 이미지가 없고 YouTube 썸네일이 있으면 YouTube 썸네일을 출력합니다.
- 둘 다 없으면 default 이미지를 출력합니다.
- 작업물 썸네일은 바로가기 성격이므로 확대 기능을 적용하지 않습니다.

### 4. 로그인 `지금 확인할 활동`

확인할 문제:

- 일반/팀장 유저 `김도윤` 로그인 시 `회사 승인 검토 요청`이 표시되는 문제
- 팀원 유저 `이지은` 로그인 시 `남산 새벽팀 추천 후보` 확인 버튼으로 해당 팀을 볼 수 없는 문제
- 우측 상단 알림에도 같은 문제가 발생하는 문제

구현:

- 계정 유형, 관리자 권한, 팀 역할에 따라 활동 항목 노출을 제한합니다.
- 일반/팀장 유저에게 회사 승인 검토 요청이 노출되지 않게 합니다.
- 팀 추천 후보 확인 버튼은 팀 상세 또는 `매칭 페이지 > 팀 찾기 > 저장한 팀`처럼 해당 팀 정보를 확인할 수 있는 경로로 연결합니다.
- 우측 상단 알림도 같은 기준으로 검증합니다.

### 5. 메인 카드

- 관리자가 이미지를 직접 지정하여 메인 카드 배경으로 사용할 수 있게 합니다.
- 사용자 답변에 따라 등록/수정 화면과 API를 결정합니다.
- 기존 좌측 텍스트/우측 이미지 구조를 배경 이미지 구조로 변경합니다.
- 비로그인 메인 카드에서 `무료로 시작하기`, `작업물 둘러보기`는 유지하고 `로그인`은 삭제합니다.

### 6. 비로그인 중복 블럭 삭제

- `다음 작품을 함께 만들 사람을 만나보세요` 블럭을 삭제합니다.
- 삭제 후 빈 공간과 간격을 정리합니다.

### 7. 공모전 하트와 저장한 공모전 통합

- 메인 페이지 하트와 공모전 페이지 `저장한 공모전` 기능을 같은 저장 상태로 병합합니다.
- 공모전 페이지 상단 탭에 `저장한 공모전`을 추가합니다.
- 하트 아이콘 디자인은 메인 페이지 디자인을 기준으로 통일합니다.
- 공모전 페이지는 사용자가 별도 작성 전인 영역이므로, 이 저장 탭과 직접 관련된 범위만 수정하세요.

### 2. 기준 팀 출력 방식

- 팀 1개 보유 사용자도 팀 선택 UI를 봅니다.
- 팀 1개면 해당 팀을 기본값으로 선택합니다.
- 팀 2개 이상이면 가장 최근 생성한 팀을 기본값으로 선택합니다.
- 팀이 없는 팀원은 기존 빈 상태/안내를 유지합니다.
- `모집 역할`은 복수 선택 가능해야 하며, 추가 필터 복수 선택 방식과 같은 UI를 사용합니다.

### 3. 지역/장르 필터

- 지역 필터의 두 탭을 하나로 합칩니다.
- DB 기준 데이터로 자동완성 목록을 제공합니다.
- 글자를 입력하면 해당 글자를 포함하는 항목을 즉시 출력합니다.
- 한글 조합 중에도 검색 결과를 즉시 갱신합니다. 예: `고양` 입력 중 `고야` 상태도 검색 기준으로 사용합니다.
- 장르 필터도 같은 방식으로 수정합니다.
- 장르 미입력 상태에서는 전체 목록을 출력합니다.

### 4. 복수 선택과 선택 칩

복수 선택 대상:

- 장르
- 합류 가능 시점, 화면 표시명은 `작업 일정`
- 협업 조건
- 모집 역할

요구사항:

- 선택 항목은 버튼 아래에 칩으로 표시합니다.
- 각 칩 우측 X로 개별 해제합니다.
- 칩은 필터별로 묶고 필터 순서대로 표시합니다.
- 필터 종류별 배경색을 다르게 합니다.

### 5. 필터 초기화

- 팀원 찾기에서 `초기화`는 추가 필터만 초기화합니다.
- 기준 팀은 유지합니다.
- 모집 역할이 기준 정보에 속하는 경우 사용자 작성 기준에 따라 유지합니다.
- 팀 찾기에서 `초기화`는 필터 영역만 초기화하고 기존 검색 결과는 유지합니다.

### 6. 팀 찾기 필터와 검색 결과 유지

- 팀 찾기에도 장르/지역/요구 경력/협업 조건 개선 방식을 동일하게 적용합니다.
- 검색 상태에서 필터 변경 시 기존 출력 내용은 제거하지 않습니다.
- `팀 검색` 버튼을 누르기 전까지 기존 결과를 유지합니다.
- `초기화` 버튼을 눌러도 기존 결과를 유지하고 필터 영역만 초기화합니다.
- 필터 값이 변경되었지만 아직 검색 결과에 반영되지 않았음을 사용자에게 표시합니다.
- 기존 문서의 장르 필터 백엔드 결함을 확인하고, 프론트가 정상이어도 백엔드에서 장르 결과가 0건으로 고정되면 함께 수정합니다.

### 7. 문구와 버튼 배치

- `합류 가능 시점` → `작업 일정`
- `1개월 이후` → `6개월 이내`
- `필터 적용` → `팀원 검색` 또는 `팀 검색`
- `필터 초기화` → `초기화`
- `AI로 팀원 추천받기` 등 → `AI 추천`
- 최소 데스크톱 폭에서 `장르`, `지역`, `경력`, `작업 일정`, `협업 조건`이 한 줄에 제시되게 합니다.
- `초기화`는 좌측 가장 왼쪽에 둡니다.
- `검색`과 `AI 추천`은 우측에 두고, `AI 추천`을 가장 오른쪽에 둡니다.

### 8. 상태 UX

- 필터 미적용
- 필터 변경 후 검색 전
- 결과 0건
- API 오류
- AI 실패 fallback
- 저장/지원 상태

위 상태가 서로 다른 메시지와 버튼 상태로 구분되어야 합니다.

### 1. 내 팀 목록

- 내 팀 목록의 `관심 팀` 기능과 별표 버튼을 삭제합니다.
- `팀 아카이브 안내`를 삭제합니다.
- 팀 저장/관심 기능의 메인은 `매칭 페이지 > 팀 찾기`의 `저장` 버튼으로 둡니다.
- 내 팀 목록에는 현재 진행 중인 팀만 표시합니다.
- 현재 진행 중인 팀은 최대 3개까지 표시합니다.
- 종료 상태 팀은 `종료된 팀` 블럭에 별도로 표시합니다.
- 내 팀 목록은 팀 생성일 최신순입니다.
- 종료된 팀은 팀 종료일 최신순입니다.
- 종료된 팀 블럭 우측에 `최신순/오래된순` 정렬 선택을 제공합니다.

### 2. 팀 목록 카드

- 좌측: 팀 대표 이미지
- 중앙: 팀 이름, 장르, 지역, 최신 일정, 모집 상황
- 우측: 진행률 원그래프
- 팀 대표 이미지에는 공통 이미지 확대 보기 정책을 적용합니다.

### 3. 팀 만들기

- `Teams/팀 생성` 블럭을 삭제하고 `팀 정보` 블럭과 병합합니다.
- `팀 정보` 블럭 최상단에 현재 글자 크기로 `Teams/팀 생성`을 표시합니다.
- 같은 줄 우측에 `팀 목록`, `팀 저장` 버튼을 둡니다.
- `생성/팀 정보` 문구를 삭제합니다.
- `팀 수정` 블럭의 `매칭` 버튼을 삭제합니다.

입력 필드 배치:

- `상태` 폭은 `모집 완료` 글자 크기에 맞춥니다.
- `상태`는 현재 줄 가장 왼쪽에 둡니다.
- `팀 이름`은 상태 오른쪽에 둡니다.
- `팀 대표 이미지/JPEG, PNG, WebP · 최대 5MB/이미지 선택`은 상태 아래 줄에 한 줄로 둡니다.
- `지역 설정`, `지역`, `예상 기간`, `최대 인원`은 상태처럼 크기를 줄입니다.
- `지역 설정`+`지역`, `예상 기간`+`최대 인원`을 각각 묶어 2단 한 줄로 둡니다.
- 장르 버튼의 체크박스를 제거하고 활성/비활성 스타일로 표시합니다.
- `이미지 미리보기`는 상태와 팀 대표 이미지 텍스트 두 줄과 같은 줄의 가장 좌측에 둡니다.
- `설명`은 가장 아래에 둡니다.

### 4. 팀 상세 상단과 설명

상단:

- `모집 상태`는 팀 이미지 상단에 둡니다.
- `정원`은 팀 이름 상단에 둡니다.
- `목록`, `팀 수정` 버튼은 팀 이름 줄 오른쪽에 둡니다.
- `팀 수정` 버튼이 가장 오른쪽입니다.
- `목록` → `팀 목록`
- `팀 수정` → `팀 정보 수정`
- `리더`는 `장르`, `지역` 왼쪽에 둡니다.

설명:

- 줄바꿈을 보존합니다.
- 500자 초과 시 `더 보기`로 접습니다.
- `더 보기` 클릭 시 전체 텍스트를 보여줍니다.
- 설명이 길어져도 팀 이미지는 위쪽 정렬로 고정합니다.
- 긴 숫자나 긴 단어도 줄바꿈되게 합니다.

### 5. 팀 상세 대기/모집/멤버 블럭

- 설명 우측의 `지원/초대 대기`, `모집 슬롯 요약`, `멤버 현황`을 현재 블럭 아래 별도 블럭으로 배치합니다.
- `지원/초대 대기` → `모집 대기`
- `모집 슬롯 요약` → `모집 현황`
- `멤버 현황` → `멤버 보기`
- `모집 관리`, `멤버 관리`, `계획 보기` 버튼은 삭제합니다.
- 해당 진입점은 이미 새 블럭으로 제공되므로 별도 버튼을 남기지 않습니다.

### 6. 계획 진행률과 일정 안내

- `전체 진행률` 그래프는 한 줄로 할당하고 좌우 중앙 정렬합니다.
- `다음 마일스톤` 텍스트는 제거합니다.
- D-Day는 계획 진행률 바로 오른쪽에 둡니다.
- 기존 원 그래프 우측의 `최신 일정 제목`, `일자`는 그래프 아래 줄로 옮깁니다.
- 일정 안내의 선/점 표시에서 텍스트가 겹치지 않게 합니다.
- 점들은 상대적인 위치를 반영합니다.
- 모바일은 손으로, 데스크톱은 마우스로 우측 일정들을 확인할 수 있게 스위핑 동작을 제공합니다.
- 일정 상태는 일자 줄 오른쪽에 배치합니다.

### 7. 팀 종료 페이지와 복구 UI

- `계획 조작`을 삭제합니다.
- 일정 안내 아래 줄 오른쪽에 `팀 작업 종료하기` 버튼을 둡니다.
- 현재 `팀 작업 종료하기` 클릭 시 팀 수정 페이지가 출력되는 문제를 수정합니다.
- 별도 `팀 종료` 페이지를 만듭니다.
- 팀 종료 페이지에는 `팀 정보` 블럭을 제외하고 `팀 종료` 블럭만 표시합니다.
- 기존 팀 수정 페이지에서는 `팀 종료` 블럭을 제거합니다.
- 팀 종료 페이지 URL과 메뉴 노출 방식은 사용자 답변을 따릅니다.

종료/복구 UI:

- `정상 종료` 클릭 시 데스크톱은 hover/popover, 모바일은 modal로 확인 UI를 표시합니다.
- 확인 UI에는 `팀 작업을 종료하시겠습니까?`, `취소`, `작업 종료`를 표시합니다.
- 종료 상태 팀의 `복구 스냅샷`, `복구 방식` 문구는 사용자 UI에서 제거합니다.
- 사용자 UI에서는 최신 팀 상태로 복구하는 단일 방식만 제공합니다.
- 감사 로그와 종료 스냅샷 보관 정보는 서비스 이용자에게 제공하지 않습니다.
- 내부 시스템의 감사 로그와 종료 스냅샷 보관 자체는 유지합니다.
- 정상 종료 안내: `팀 작업이 종료된 팀입니다.`, 초록 계열
- 해체 안내: `해체된 팀입니다.`, 빨간 계열
- `팀 재개` → `팀 복구`
