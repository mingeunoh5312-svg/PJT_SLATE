# Lovable 입력 프롬프트

## 작업 요청

Slate 서비스를 위한 새로운 페이지 디자인 시안을 제작해주세요.

Lovable의 작업 범위는 페이지 디자인 시안 제작입니다. 실제 기능 구현은 하지 않습니다. 백엔드, API 연동, 데이터 저장, 인증 처리, 파일 업로드, 외부 API 호출, 권한 처리, 유효성 검증 로직은 구현하지 마세요. 화면을 표현하기 위해 필요한 최소한의 정적 mock data만 사용해주세요.

## 참고 문서

함께 업로드된 문서만 참고해주세요.

- `service_brief.md`: Slate의 목적, 사용자 유형, 제공 기능, 핵심 업무 흐름
- `upload_manifest.md`: 업로드 문서와 제외 대상

문서 외의 참조 파일, 코드, 이미지, 기존 화면 캡처, 기존 디자인 자료는 업로드하지 않았고 사용하지 않습니다.

## 중요한 조건

- 기존 Slate UI를 재현하지 마세요.
- 기존 페이지 수, 기존 route, 기존 화면 구성, 기존 메뉴 구조를 유지할 필요가 없습니다.
- 서비스 목적과 제공 기능을 이해한 뒤, 필요한 페이지를 새로 정의해주세요.
- 현재 존재하는 페이지를 모두 만들 필요는 없습니다.
- 필요하다고 판단하면 기존에 없던 페이지를 추가해도 됩니다.
- 필요하다고 판단하면 기존 기능을 더 적은 페이지로 통합하거나, 복잡한 관리 기능을 별도 업무 흐름으로 분리해도 됩니다.
- 디자인 컨셉, 페이지 구성, 정보 우선순위, 시각 스타일, 컴포넌트 선택, 화면 간 흐름은 Lovable이 직접 판단해주세요.
- 이 프롬프트는 디자인 판단을 제한하기 위한 문서가 아니라, 서비스 도메인과 기능 범위를 설명하기 위한 문서입니다.

## 디자인 시안의 목표

Slate가 어떤 서비스인지 처음 보는 사람이 페이지 시안만 보고도 다음을 이해할 수 있어야 합니다.

- 영화/영상 제작자와 팀이 서로를 찾는 서비스다.
- 사용자는 프로필과 포트폴리오를 만들고, 제작 역할과 참여 가능 조건을 표현할 수 있다.
- 팀은 프로젝트를 만들고, 모집 공고와 지원/초대, 일정, 팀 작업물을 관리할 수 있다.
- 매칭은 팀이 팀원을 찾는 방향과 제작자가 팀을 찾는 방향을 모두 지원한다.
- AI는 매칭 추천, 공모전 적합도, 로케이션 탐색 같은 의사결정을 보조한다.
- 작업물 게시판은 결과물을 공유하고 리뷰, 좋아요, 랭킹, 신고 흐름을 가진다.
- 공모전 영역은 공모전 탐색, 저장, 제출 준비, 기업의 공모전 개설 요청, 운영자의 승인/관리 흐름을 가진다.
- 관리자는 회원, 팀, 게시글, 파일, 신고, 공모전, 기업 승인, 알림, 권한, 로그, 점수 정책을 운영한다.

## 산출물 범위

Lovable이 서비스 이해에 가장 적합하다고 판단하는 대표 페이지 디자인 시안을 만들어주세요. 모든 기능을 개별 페이지로 만들 필요는 없습니다.

산출물은 디자인 시안이어야 하며, 아래는 구현하지 않습니다.

- 실제 로그인 처리
- 실제 회원가입 처리
- 실제 API 요청
- 실제 파일 업로드
- 실제 YouTube/KOBIS/OpenAI/Kakao/VWorld 호출
- 실제 지도 SDK 연동
- 실제 관리자 권한 판정
- 실제 알림 발송
- 실제 데이터 영속화

필요한 경우 화면 상태를 보여주기 위해 정적 예시 데이터, 비활성 버튼, 시각적 상태 표현, placeholder media는 사용할 수 있습니다.

## 텍스트와 데이터

- 화면 문구는 한국어 기준으로 작성해주세요.
- 서비스명은 `Slate`입니다.
- 영화/영상 제작 현장의 용어를 자연스럽게 사용해주세요.
- 사용자 이름, 팀 이름, 작품명, 공모전명, 역할명, 지역명 등은 실제 서비스처럼 보이는 예시를 사용해도 됩니다.
- 민감 정보, 실제 API key, 실제 계정 비밀번호, 실제 사업자 정보는 포함하지 마세요.

## 최종 확인 기준

완성된 시안은 기능 구현물이 아니라 디자인 방향을 검토하기 위한 결과물이어야 합니다.

검토자는 완성된 시안을 보고 다음을 판단할 수 있어야 합니다.

- Slate의 서비스 가치가 명확한가
- 주요 사용자 유형별 목적이 드러나는가
- 핵심 기능 영역이 서로 어떻게 연결되는지 이해할 수 있는가
- 복잡한 제작/운영 기능이 사용자가 이해할 수 있는 업무 단위로 정리되어 있는가
- 이후 실제 프론트엔드 구현자가 화면을 설계할 때 참고할 수 있을 만큼 충분한 상태와 콘텐츠 예시가 있는가
