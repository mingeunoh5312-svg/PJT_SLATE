# 프로필 대시보드 실제 데이터·팔로우·Verified 수정

## 작업 범위

- `frontend/src/views/ProfileView.vue`
- `frontend/src/styles/slate.css`
- 백엔드, SQL, seed 변경 없음

## 수정 내용

- 프로필 대시보드의 샘플 사용자, 팀, 작품, 포트폴리오 이미지와 고정 문구를 제거했다.
- `myProfile`, `myTeams`, `boardPosts`, 프로필의 `portfolioItems` 응답으로 대시보드를 구성했다.
- 참여 작품은 현재 사용자가 작성했거나 현재 참여 팀에 연결된 `WORK` 게시물만 표시한다.
- 프로필, 팀, 작품, 포트폴리오가 없거나 조회에 실패한 경우 각각의 빈 상태와 오류 상태를 표시한다.
- 참조 코드 조회 실패가 프로필 및 팔로우 요약 조회를 막지 않도록 로딩 순서를 분리했다.
- 프로필 저장값이 비어 있을 때 첫 역할, 장르, 협업 조건을 임의 선택하던 동작을 제거했다.
- 백엔드 근거 없이 프런트에서 계산하던 프로필 완성도 비율을 제거했다.
- 실제 프로필 ID가 있을 때만 팔로우 요약 및 목록 API를 사용하며, 오류가 발생해도 요약 영역은 유지한다.
- 포트폴리오의 백엔드 `verified: true` 값만 Verified로 판단하고 대시보드, 관리 목록, 상세 화면에 같은 배지를 표시한다.
- 썸네일이 없는 팀, 작품, 포트폴리오는 가짜 이미지 대신 중립적인 플레이스홀더를 표시한다.

## 검증

- `npm run build`: 성공
- `git diff --check -- src/views/ProfileView.vue src/styles/slate.css`: 성공
- 샘플 이름, 역할, 지역, 팀, 작품 및 fallback 배열 잔존 검색: 0건
- 백엔드 `ProfileMapper.xml`의 portfolio 조회 세 경로가 모두 boolean `verified`를 반환함을 확인
- `/api/boards/posts` 최대 조회 수 50 및 팀/작품 응답 필드 계약 확인
- 로컬 프런트 `http://127.0.0.1:5174/profile`: HTTP 200 확인
- 로컬 백엔드 `http://127.0.0.1:8080`: 실행 중 확인(비인증 요청 403)
- 내장 브라우저 연결은 실행 환경 메타데이터 오류로 사용할 수 없어 desktop/390x844 시각 검증과 콘솔 확인은 수행하지 못했다. 대신 920px/560px 반응형 규칙과 플레이스홀더 폭을 정적 점검했다.

## 참고

- 작업 시작 전부터 존재한 다른 프런트/백엔드 변경은 되돌리거나 수정하지 않았다.
- Vite 빌드의 500kB 초과 chunk 경고는 기존 번들 구성 경고이며 빌드 실패가 아니다.
