## 반영 내용

### 추천 인재 카드와 팀원 후보 상세

- 추천 인재 카드 우측 액션 영역을 적합도와 버튼 영역으로 분리했다.
- 버튼은 세로 배치로 정리했다.
- 버튼 순서는 `상세 보기`, `팔로우`, `초대`로 맞췄다.
- 기존 `저장` 버튼은 팀원 후보 맥락에서 실효성이 낮아 `팔로우` 버튼으로 교체했다.
- 팀원 후보 상세에서도 `저장` 버튼을 제거하고 팔로우/초대 중심으로 정리했다.
- 팔로잉 상태의 테두리와 배경 색상을 추천 카드의 팔로우 버튼과 같은 파란색 계열로 맞췄다.
- 팀원 후보 상세 진입 시 `팀원 찾기/팀 찾기` 상위 버튼이 보이지 않도록 하고, `목록` 버튼으로 이전 매칭 목록 맥락을 유지해 돌아가도록 했다.

### 초대/지원 상태와 재클릭 취소

- 팀원 찾기의 `초대` 버튼은 이미 초대한 상태에서 `초대됨`으로 표시한다.
- 팀 찾기의 `지원` 버튼은 이미 지원한 상태에서 `지원됨`으로 표시한다.
- 초대/지원 버튼은 팔로우 버튼처럼 활성 상태를 색상으로 표시한다.
- `초대됨` 재클릭 시 대기 중 초대를 취소할 수 있도록 했다.
- `지원됨` 재클릭 시 대기 중 지원을 취소할 수 있도록 했다.
- 추천 목록, 상세 페이지, 저장한 팀 탭의 지원 버튼 상태를 같은 상태값으로 연동했다.
- 초대/지원 성공 또는 취소 시 별도 안내 문구를 출력하지 않도록 했다. 오류 문구는 유지했다.

### 초대한 팀원/지원한 팀 탭

- 팀원 찾기 하위 탭에 `초대한 팀원`을 추가했다.
- 팀 찾기 하위 탭에 `지원한 팀`을 추가했다.
- 로그인 사용자가 보낸 초대와 지원 목록을 간략한 요약 카드로 표시한다.
- 각 목록은 상태, 대상 이름, 역할, 모집 공고, 생성 시각을 표시한다.
- 상태 필터 체크박스를 우측 상단에 추가했다.
- 상태 필터는 `대기 중`, `수락됨`, `거절됨`, `취소됨`, `만료됨`을 기준으로 하며 각 상태별 건수를 표시한다.
- 데스크톱에서는 상태 체크박스가 한 줄에 출력되도록 했다.
- 모바일에서는 기존처럼 줄바꿈을 허용한다.
- 각 카드의 이미지 영역과 텍스트 영역을 분리해 이미지 위에 텍스트가 겹치지 않도록 했다.
- 카드 클릭 또는 키보드 Enter/Space 입력 시 대상 팀원/팀 상세 페이지로 이동하도록 했다.
- 카드 내부의 취소 버튼은 클릭 이벤트 전파를 막아 상세 이동과 충돌하지 않도록 했다.

### 팀 찾기 추천 팀과 저장한 팀

- 팀 찾기 탭 접근 시 기본값으로 전체 추천 팀 목록을 출력하도록 정리했다.
- 추천 팀 카드의 `저장/저장됨` 버튼은 색상으로 상태를 표시하도록 했다.
- 추천 팀의 저장 버튼을 다시 클릭하면 저장 취소가 가능하도록 했다.
- 추천 팀 카드의 저장 버튼에서 하트 문자를 제거했다.
- 저장한 팀 탭에서 상세보기/지원 버튼은 우측 정렬, 저장 취소 버튼은 좌측 정렬로 정리했다.
- 저장한 팀의 긴 설명은 100자 기준으로 접고 펼 수 있게 했다.
- `더 보기` 버튼은 생략된 `...` 뒤에 이어서 출력되도록 했다.
- 추천 팀의 긴 설명은 80자 초과 시 `...`으로 생략했다.
- 띄어쓰기 없는 긴 팀 설명이 카드 영역을 뚫고 나가지 않도록 줄바꿈 처리를 보강했다.

### AI 추천/추천 목록 헤더

- 팀원 찾기 탭의 AI 추천 하단 설명을 `설정한 팀을 기준으로 추천합니다.`로 수정했다.
- 추천 팀/추천 인재 헤더와 AI 추천 헤더의 높이가 다르게 보이던 문제를 최소 높이 기준으로 맞췄다.
- `AI 추천` 버튼은 추천 목록 헤더의 오른쪽에 유지했다.

### 공개 프로필과 포트폴리오 요약

- 팀원 후보 상세의 `전체 포트폴리오 보기`가 현재 로그인 사용자의 내 정보로 이동하던 문제를 수정했다.
- 타인의 공개 프로필 포트폴리오 목록으로 이동하도록 연결했다.
- 공개 프로필 포트폴리오 목록이 없던 경우를 위해 공개 프로필 포트폴리오 표시 영역을 보강했다.
- 팀원 후보 상세의 포트폴리오 요약은 더미 데이터 대신 실제 포트폴리오 데이터를 기준으로 집계한다.
- 포트폴리오 요약은 작품 유형/출처/역할 계열 기준으로 묶고 기본 3개가 보이는 가로 스크롤 카드로 표시했다.

### 파란색 점 제거

- 팀원 및 팀 이름 오른쪽에 있던 파란색 점은 장식용 상태 표시였으며, 별도 의미가 명확하지 않아 제거했다.

### 백엔드 API와 매퍼

- 로그인 사용자가 보낸 초대 목록 조회 API를 추가했다.
- 로그인 사용자가 보낸 지원 목록 조회 API를 추가했다.
- 대기 중 초대 취소 API를 추가했다.
- 대기 중 지원 취소 API를 추가했다.
- 매칭 후보와 모집 역할 응답에 현재 사용자의 초대/지원 상태와 식별자를 포함하도록 보강했다.
- 저장한 팀의 open role 조회에서도 현재 사용자의 지원 상태가 내려가도록 했다.
- 초대 취소는 해당 팀의 팀장/부팀장 권한을 확인하고 대기 상태만 취소하도록 했다.
- 지원 취소는 지원자 본인만 대기 상태 지원을 취소할 수 있도록 했다.

### 로컬 서버 상태 확인

- 사용자 요청에 따라 로컬 백엔드 상태를 확인했다.
- `5174` 프론트엔드는 리스닝 상태였으나 `8080` 백엔드는 포트를 열지 못한 상태였다.
- 잔여 Java/Maven 프로세스를 종료한 뒤 백엔드를 `8080`으로 재기동했다.
- 재기동 후 `Tomcat started on port 8080` 로그와 `8080 Listen` 상태를 확인했다.
- 인증 없이 `/api/matching/candidates`를 직접 호출하면 `403`이 반환되는 것을 확인했다. 이는 서버 미기동이 아니라 인증이 필요한 API 응답으로 판단했다.

## 남은 확인 사항

- 최신 초대한 팀원/지원한 팀 상세 이동은 빌드 검증까지 완료했으며, 실제 브라우저 클릭 회귀 검증은 별도로 수행하지 않았다.
- 초대 취소는 팀장/부팀장 권한 기준으로 처리되므로 같은 팀의 다른 관리자가 보낸 초대도 팀 권한자라면 취소 가능한 상태다. 이 정책을 더 엄격하게 `초대한 본인만 취소`로 바꿀지는 별도 사용자 판단이 필요하다.
- 저장한 팀 탭에서 선택한 open role이 목록에서 사라진 경우에는 해당 탭의 지원 취소 버튼이 표시되지 않을 수 있다. 이 경우 `지원한 팀` 탭에서 대기 중 지원 취소가 가능하다.
- `.codex-server-logs/`는 로컬 서버 작업 중 생성된 작업 환경 로그로 보이며, 이번 문서 작업 대상에는 포함하지 않았다.
