# 팀 상세·계획·목록 화면 UI 정리 작업 로그

작성일: 2026-06-24

## 문서 작성 기준

- 사용자 지시가 명시한 팀 페이지 범위만 정리한다.
- 팀 상태 전환, 종료/복구 정책, 멤버 권한, 모집/지원/초대 처리 로직, API 계약, DB 스키마는 완료 범위로 쓰지 않는다.
- 구현된 화면 변경과 미수행 검증을 분리해 기록한다.
- 실제 비밀값, 토큰, 환경변수 값은 기록하지 않는다.

## 작업 범위

- 대상 화면:
  - 팀 목록
  - 팀 생성
  - 팀 정보
  - 팀 종료
  - 팀 계획/전체 일정
  - 새 계획
  - 팀 상세의 멤버, 모집 공고, 지원/초대 현황, 일정 안내 영역
- 주요 파일:
  - `frontend/src/views/TeamsView.vue`
  - `frontend/src/router/index.js`
  - `frontend/src/styles/slate.css`
- 제외 범위:
  - 백엔드 컨트롤러/서비스/매퍼
  - API 계약
  - DB 스키마
  - 팀 상태 전환 정책
  - 지원/초대/모집 처리 정책

## 반영 내용

### 팀 생성

- 팀 생성 폼의 상태 선택에서 `종료` 상태가 출력되지 않도록 했다.
- 팀 생성 기본 상태는 기존 API 계약을 유지한 채 생성 가능한 상태 코드에서 선택하도록 정리했다.

### 팀 정보 화면

- 팀 상세 라우트 표시 텍스트를 `팀 상세`에서 `팀 정보`로 수정했다.
- 팀 정보 화면의 상단 요약 카드와 핵심 정보 카드를 재구성했다.
- 대표 이미지가 카드 영역을 벗어나지 않도록 이미지 버튼과 이미지 자체의 비율, overflow 처리를 보정했다.
- 팀 설명의 `더 보기` 전환 기준을 150자로 조정했다.
- 멤버 카드는 멤버 명단으로 이동하도록 유지하고, 인원 표기를 `N명 (최대 정원 M명)` 형태로 정리했다.
- 모집 카드는 `모집 공고`로 표기하고 모집 관리 화면으로 이동하도록 정리했다.
- `지원/초대 관리` 블럭은 팀 정보 화면에서 표시하지 않도록 했다.
- `지원/초대 현황` 카드는 별도 관리 팝업으로 열지 않고 상태 요약 카드로 유지했다.
- 계획 블럭은 팀 정보 화면에서 제거하고, 일정 관련 진입은 `다음 일정`과 일정 안내 영역으로 정리했다.

### 일정 안내

- 일정 안내의 텍스트 카드가 가까운 일정끼리 겹치지 않도록 가로 스크롤 기반 배치로 정리했다.
- 데스크톱에서도 모바일처럼 드래그로 우측 일정을 확인할 수 있도록 pointer drag 스크롤을 추가했다.
- 기존 실선/포인트 시각화를 복구하고, 텍스트 카드와 겹치지 않도록 카드 상단에 배치했다.
- 포인트 중심이 실선 위에 놓이도록 보정했다.
- 포인트 지름을 기존 대비 0.7배 수준으로 조정했다.
- 선과 선 사이에 생기던 여백을 제거했다.
- `팀 작업 종료하기` 버튼은 일정 안내 카드 외부 우측 하단에 배치했다.

### 팀 종료 화면

- 팀 종료 화면의 별도 `Closure/팀 종료` 블럭을 제거하고 `Team Closure/팀 종료` 단일 블럭으로 병합했다.
- `정상 종료` 버튼 문구를 `팀 작업 종료하기`로 변경했다.
- 종료 유형 표시 중 `해체`는 `팀 해체`로 표시하도록 했다.
- 팀 종료 화면의 `팀 목록` 버튼은 제거하고, 기존 `상세` 버튼은 `돌아가기`로 변경했다.
- 종료/복구 API와 권한 정책은 변경하지 않았다.

### 팀 계획/전체 일정 화면

- 팀 계획 화면을 전체 일정 중심으로 재구성했다.
- `/teams/:teamId/plans` 화면을 `Team Plans/전체 일정` 단일 블럭으로 병합했다.
- 기존 `팀 목록` 버튼은 제거하고, `팀 정보` 버튼을 `새 계획` 왼쪽에 배치했다.
- 전체 계획 수, 진행 중, 완료, 다음 일정 요약 카드를 추가했다.
- 일정 목록은 마감일 순으로 정렬하고, 마감일이 없는 계획은 하단에 배치했다.
- 계획 상태 변경은 기존 `updateTeamPlanStatus` 호출을 유지하면서 선택 UI로 정리했다.

### 새 계획 화면

- 새 계획은 `/teams/:teamId/plans/new` 별도 라우트에서 작성하도록 분리했다.
- 새 계획 화면을 `New Plan/새 계획` 단일 블럭으로 병합했다.
- `팀 목록` 버튼은 제거했다.
- `팀 정보` 버튼을 `전체 일정` 왼쪽에 배치했다.
- 설명 입력란을 폼 하단으로 이동했다.
- 마감일 `datetime-local` 입력은 직접 입력을 유지하면서, 지원 브라우저에서 클릭 시 기본 picker가 열리도록 `showPicker()`를 연결했다.
- 계획 생성 후 전체 일정 화면으로 돌아가도록 했다.

### 팀 목록

- 팀 목록 화면 상단 제목을 `팀`에서 `팀 목록`으로 변경했다.
- `팀 만들기` 버튼을 상단 우측에 정렬했다.
- 진행 중 팀 목록은 `내 팀 목록` 카드에 유지했다.
- `종료된 팀`은 `내 팀 목록` 하단의 별도 카드 블럭으로 분리했다.
- 진행 중/종료 팀 표시 기준과 정렬 정책은 기존 로직을 유지했다.

## 검증 결과

- 프론트엔드 빌드:
  - 명령: `npm.cmd run build` in `Slate/frontend`
  - 결과: 성공
  - 참고: Vite chunk size 경고는 기존 번들 크기 경고이며 빌드는 통과했다.
- 백엔드 검증:
  - 수행하지 않음.
  - 사유: 이번 작업은 프론트 화면, 라우트, 스타일 변경으로 제한했고 백엔드/API/DB를 수정하지 않았다.
- 브라우저 수동 검증:
  - 수행하지 않음.
  - 사유: 이번 대화에서는 사용자가 열려 있다고 알린 서버 포트만 참고했고, 별도 브라우저 smoke는 실행하지 않았다.

## 이번 작업에서 의도적으로 변경하지 않은 내용

- 팀 상태 전환, 종료/복구 정책, 모집/지원/초대 처리 로직은 변경하지 않았다.
- 멤버 권한과 팀장/부팀장 권한 조건은 변경하지 않았다.
- API 요청/응답 계약과 DB 스키마는 변경하지 않았다.
- 임의 기본 이미지는 추가하지 않았다.
- 팀 목록의 진행 중/종료 팀 판정 기준은 기존 상태 코드 기준을 유지했다.

## 남은 확인 사항

- 실제 로그인 계정과 데이터가 있는 브라우저에서 팀 정보, 전체 일정, 새 계획, 팀 종료 화면의 최종 시각 QA가 필요하다.
- 일정 안내의 포인트/실선 위치는 화면 폭과 일정 개수에 따라 실제 데이터 기반 추가 확인이 필요하다.
- 작업 트리에 팀 페이지 외 다른 파일 변경이 이미 존재했으나, 이번 문서의 완료 범위에는 포함하지 않았다.
